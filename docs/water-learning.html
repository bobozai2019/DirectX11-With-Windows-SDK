01 / 建立直觉

先把“计算波纹”和“画出水面”分开。

这两个工程都会维护一张随时间变化的高度数据纹理。第一阶段更新它，回答“下一步每个位置该是什么值”；第二阶段读取它，回答“这个位置的顶点、法线和颜色该是什么”。你看到的抖动，是数据传播与着色共同产生的结果。

沿箭头看一遍，再回到代码：Main.cpp → GameApp::Init → D3DApp::Run → UpdateScene → Advance → Step → DrawScene。图中的蓝色节点是关键 GPU 工作。

渲染帧 ≠ 模拟步。Advance(dt) 累积 min(dt, 0.1)，每满足 1/60 秒推进一次模拟；因此一个渲染帧可能做 0 次、1 次或多次 Step。页面后面的 F0–F6 指模拟状态，步间约 16.67 ms，不代表显卡实际 FPS。

图中简化了 Win32 消息分发与错误返回：主循环遇到消息先处理；退出消息结束循环；应用失焦/最小化的框架暂停与 UI 的 Pause 是两层状态。UI Pause 只停止模拟，仍可显示水面、调整视角。

DynamicDraw 一个 Step 里做什么？

  1. Unbind() 清除上次读写绑定，更新 SimParams。
  2. 新的碰撞纹理作为 RTV，运行 Collision_PS：把旋转椭圆范围写成船体速度编码 Boat.w。
  3. 绑定当前/历史高度、新/旧碰撞、陆地共 5 个 SRV。下一张高度作为 RTV，运行 Dynamic_PS。
  4. 解绑，更新碰撞索引，并轮换三张高度纹理的角色。

Compute 一个 Step 里做什么？

  1. Unbind()，上传尺寸、衰减、扰动位置等常量。
  2. CSSetShaderResources 绑定当前与历史两张高度；CSSetUnorderedAccessViews 绑定下一张。
  3. 每个线程计算一个 texel，写 Output[id.xy]。
  4. 解绑 UAV/SRV、清除 CS，再轮换高度纹理。随后正常使用 VS/PS 绘制水面。
03 / 最值得理解的 GPU 状态

三个“角色”，不是每步复制三张图。

波动公式需要当前状态和上一步状态；新结果写进第三张纹理。完成后交换索引，原来的“历史”就可以充当下一次输出。这是角色轮换，不是 CopyResource。本工程只在验证读回时复制到 staging 纹理。

// 初始化：current=0, previous=1, next=2
// Step：读 height[current] 和 height[previous]，写 height[next]
int free = previous;
previous = current;
current = next;

Texture 是数据；View 是使用入口。

SRV：让 Shader 读取纹理，代码里对应 Texture2D。

RTV：让光栅化后的 PS 输出落进纹理，常见于渲染到纹理。

UAV：允许 Shader 按坐标写数据，这里对应 RWTexture2D<float>。

同一底层纹理可以创建多种 View，但本例每一步都把输入与输出放在不同纹理上。

为什么每次 Step 前后都解绑？

同一子资源不能在这里一边作为 SRV 输入、一边作为 RTV/UAV 输出。切换角色前清空槽位，可以避免绑定冲突；D3D11 的某些冲突绑定会被置空。

Unbind() 不会抹掉像素数据，也不是 CPU 等待 GPU 完成的函数；它改变的是管线绑定状态。

接口依据：Microsoft · PSSetShaderResources 的重叠 View 规则。

把 19×19 纹理交给 8×8 线程组。

[numthreads(8,8,1)] 是每组的尺寸。Dispatch(3,3,1) 是组数，不是只有 9 个线程。

groups = (19 + 7) / 8 = 3  // 整数除法
 启动：24 × 24 = 576 个线程
 有效：19 × 19 = 361 个 texel
 退出：576 − 361 = 215 个线程

if (id.x >= N || id.y >= N) return;

全局像素坐标：SV_DispatchThreadID = GroupID × (8,8,1) + GroupThreadID。19×19 是本工程数值测试尺寸，正常 UI 提供 128、256、512。

资料：numthreads · SV_DispatchThreadID。没有线程间共享写入依赖，因此本 Shader 不使用组内同步屏障。

04 / 核心实验室 · F0 → F6

一格水受到扰动，接下来六步会怎样？

每张图是 7×7 教学纹理，F0 全零。F1 注入，F2–F6 传播。横向 x、纵向 y 均从 0 到 6；默认选择中心 (3,3)。图块数值显示 3 位小数，计算保留更多位数。点击任意图块中的格子，下方会展示这一步的计算账单。

教学模型的边界：数值由 JavaScript 按当前 HLSL 更新顺序计算，不是 GPU 抓帧。7×7 是完整的小型示意域，越界邻居使用与 Shader 相同的 clamp。DynamicDraw 默认 A 取实际 N=256、waveSpeed=0.065 对应的系数，不用 N=7 重算；它展示相同的局部运算，并非原场景的等比例缩小。JS 浮点与教学 UNORM 舍入不保证 GPU 位级一致。
播放到 F6 自动停止；两种方案同步选帧。

实验 A · DynamicDraw 的 R / G / R−G

R′ = A × Σ四邻居R + (2 − 4A) × R当前 − R历史
G′ = A × Σ四邻居G + (2 − 4A) × G当前 − G历史
船体进出 / 鼠标覆盖 → 陆地清零 → 分别写入 UNORM
最终可见波高 H = R − G

关键细节：R、G 是分别传播、分别截断的非负通道。不能先把 R−G 合成一个有符号数，再只计算一次公式并拆回 R/G；有截断、量化和扰动覆盖时，两者不等价。

工程默认 A = (0.065 × 256 / 60)² ≈ 0.076914。滑块改变传播系数，便于观察；不是更改项目文件。陆地示例将整列清零，不再是原图中的岛形。

正值 / R 更大负值 / G 更大白色≈0；× 陆地；黑框为所选坐标；色标 H:[−1,1]、R/G:[0,1]

从输入到写回

船体模式：为什么离开处出现 G？

本页用“单格遮罩”说明进出判定：F1 的中心格从 0 变为 0.8，触发 R=Amplitude×now=0.5×0.8=0.4；F2 船体移到右边，原中心从 0.8 变为 0，触发 G=0.5×old=0.4。右边新进入的格子触发 R=0.4。之后遮罩保持不变，不会每步重复注入。

原工程的 Collision_PS 生成旋转椭圆，船体沿连续轨迹运动；本页的单格移动仅用于解释同一判定逻辑。

if (now > 0 && old == 0)      z.r = Amplitude * now;
else if (now == 0 && old > 0) z.g = Amplitude * old;
// 鼠标只覆盖 R；随后陆地可以把 R/G 同时清零。
RGBA8_UNORM 为什么会改变波形？

一个通道只有 256 个可表示值。教学写回函数是 Q(x)=round(clamp(x,0,1)×255)/255。例如 0.738468 会写成约 0.737255。负值变成 0，超过 1 的值变成 1；每一步都重复这件事，因此小波可能消失，也可能出现平台。

这不是透明度的效果。模拟目标是 UNORM 数据纹理；最终输出到屏幕时的 sRGB 色彩处理是另一件事。

格式定义：Microsoft · DXGI_FORMAT。

实验 B · Compute 的单通道波纹

raw = 2 × H当前 − H历史 + 0.25 × (Σ四邻居H − 4 × H当前)
damped = raw × (1 − Damp × 0.001)
如果本格被点击 / 雨滴命中：damped = Drop.z
H下一步 = max(damped, 0)

这里的 0.25 是代码中的固定系数。中心 F1 注入 3（对应一次雨滴），后续停止加雨，便于跟踪同一脉冲。实际鼠标注入值是 5；随机雨滴约每 0.1 秒产生一次。

Damp=1：每次公式结果乘 0.999。扰动覆盖发生在衰减之后。
波高越高颜色越深固定色标 H:[0,3]；格内是高度数据，不是最终屏幕亮度。

从输入到写回

先做一个手算：默认 Damp=1，F2 中心的四邻居仍为 0，历史为 0：(2×3 + 0.25×(0−4×3))×0.999 = 2.997。F2 右邻格：(0.25×3)×0.999 = 0.74925。这里读取的是整张 F1，不能把刚算出的 F2 中心混进邻居计算。

到了某些步，raw 会算出负数，而工程明确做了 max(next,0)。R32_FLOAT 格式本来能存负值，不允许负波是此 Shader 的选择。所以它也不是完全对称、能量守恒的理想波动模型。

05 / 从纹理数值到看得见的抖动

有时顶点真的动，有时只是法线在动。

下面取实验室当前帧的第 y=3 行。折线表示高度数据的剖面；箭头表示按相邻采样差估计的法线方向。竖向高度和箭头倾斜做了夸张，便于观察，不是工程真实坐标比例，也不是 GPU 渲染结果。切换帧会同步更新。

DynamicDraw：几何 + 法线

示意顶点跟随 H=R−G。实际 VS 还乘边缘衰减，并在 Hull 不为 0 的位置禁止位移；本剖面省略这些遮罩条件。

Compute：平面 + 法线

蓝色虚线是高度数据；深色水平实线才是水面几何。箭头发生变化，水面顶点依然停留在 y=0。

① DynamicDraw 的顶点位移

// Water_VS.hlsl · 水面分支
if (Hull.SampleLevel(LinearClamp, uv, 0).r == 0) {
    float edge = saturate(min(min(uv.x,uv.y),
                       min(1-uv.x,1-uv.y)) * 30);

}

网格由 SV_VertexID 程序化生成：128×128 个格子，每格两个三角形，共 128×128×6 个顶点调用。模拟分辨率改变不会自动增加几何格子数。

② 两者都用高度差构造法线

float height = H(uv);
float dx = H(uv + float2(eps,0)) - height;
float dz = H(uv + float2(0,eps)) - height;
float3 n = normalize(float3(-dx, 1, -dz));

右侧采样更高 → dx>0 → 法线朝左倾。之后 dot(n,l)、reflect(-l,n)、reflect(-v,n) 改变，高光/环境反射随之移动，于是平面也能“看起来在波动”。

本页剖面使用相邻教学格；此处三个滑块代表实际采样得到的三个高度。工程里 DynamicDraw 的 eps=0.01（N=256 时约跨 2.56 个 texel），Compute 的 eps=1/N（一个 texel）。代码没有再除以 eps，因此这是用于视觉着色的坡度近似，不是严格以世界单位计算的曲面微分。

void WaterSimulation::Step(const SimParams &params)
{
    Unbind();
    context->UpdateSubresource(constants.Get(), 0, nullptr, &params, 0, 0);
    ID3D11Buffer *cb = constants.Get();
    context->PSSetConstantBuffers(0, 1, &cb);
    D3D11_VIEWPORT vp = {0, 0, float(size), float(size), 0, 1};
    context->RSSetViewports(1, &vp);
    context->RSSetState(raster.Get());
    context->OMSetBlendState(nullptr, nullptr, ~0u);
    context->OMSetDepthStencilState(nullptr, 0);
    context->IASetInputLayout(nullptr);
    context->IASetPrimitiveTopology(D3D11_PRIMITIVE_TOPOLOGY_TRIANGLELIST);
    context->VSSetShader(fullVS.Get(), nullptr, 0);
    {
        int nc = 1 - collisionIndex;
        auto rtv = collision[nc].rtv.Get();
        context->OMSetRenderTargets(1, &rtv, nullptr);
        context->PSSetShader(collisionPS.Get(), nullptr, 0);
        context->Draw(3, 0);
        context->OMSetRenderTargets(0, nullptr, nullptr);
        ID3D11ShaderResourceView *views[] = {height[current].srv.Get(), height[previous].srv.Get(),
                                             collision[nc].srv.Get(), collision[collisionIndex].srv.Get(), land.Get()};
        context->PSSetShaderResources(0, 5, views);
        auto sampler = point.Get();
        context->PSSetSamplers(0, 1, &sampler);
        rtv = height[next].rtv.Get();
        context->OMSetRenderTargets(1, &rtv, nullptr);
        context->PSSetShader(dynamicPS.Get(), nullptr, 0);
        context->Draw(3, 0);
        collisionIndex = nc;
    }
    Unbind();
    context->CSSetShader(nullptr, nullptr, 0);
    int free = previous;
    previous = current;
    current = next;
    next = free;
}

#include "Simulation.hlsli"
float4 PS(Fullscreen i) : SV_Target {
    int2 p=int2(i.position.xy);
    float2 z=A*(Current.Load(int3(Bound(p+int2(1,0)),0)).rg+
        Current.Load(int3(Bound(p-int2(1,0)),0)).rg+
        Current.Load(int3(Bound(p+int2(0,1)),0)).rg+
        Current.Load(int3(Bound(p-int2(0,1)),0)).rg)+
        (2-4*A)*Current.Load(int3(p,0)).rg-Previous.Load(int3(p,0)).rg;
    float now=Collision.Load(int3(p,0)).r, old=OldCollision.Load(int3(p,0)).r;
    if(now>0 && old==0) z.r=Amplitude*now;
    else if(now==0 && old>0) z.g=Amplitude*old;
    // Optional mouse disturbance; the hull-driven path is unchanged.
    if(Drop.z>0 && all(p==int2(Drop.xy))) z.r=Drop.z;
    if(UseLand && Land.SampleLevel(PointClamp,i.uv,0).r>0) z=0;
    return float4(z,0,1); // RGBA8 target performs original UNORM clamping.
}

{
    Unbind();
    context->UpdateSubresource(constants.Get(), 0, nullptr, &params, 0, 0);
    ID3D11Buffer *cb = constants.Get();
    context->CSSetConstantBuffers(0, 1, &cb);
    {
        ID3D11ShaderResourceView *views[] = {height[current].srv.Get(), height[previous].srv.Get()};
        context->CSSetShaderResources(0, 2, views);
        auto uav = height[next].uav.Get();
        context->CSSetUnorderedAccessViews(0, 1, &uav, nullptr);
        context->CSSetShader(computeCS.Get(), nullptr, 0);
        context->Dispatch((size + 7) / 8, (size + 7) / 8, 1);
    }
    Unbind();
    context->CSSetShader(nullptr, nullptr, 0);
    int free = previous;
    previous = current;
    current = next;
    next = free;
}

#include "Simulation.hlsli"
RWTexture2D<float> Output : register(u0);
[numthreads(8,8,1)]
void CS(uint3 id : SV_DispatchThreadID) {
    if(id.x>=N || id.y>=N) return;
    int2 p=id.xy;
    float v=Current.Load(int3(p,0)).r;
    float sum=Current.Load(int3(Bound(p+int2(1,0)),0)).r+
        Current.Load(int3(Bound(p-int2(1,0)),0)).r+
        Current.Load(int3(Bound(p+int2(0,1)),0)).r+
        Current.Load(int3(Bound(p-int2(0,1)),0)).r;
    float next=2*v-Previous.Load(int3(p,0)).r+.25*(sum-4*v);
    next-=Damp*next*.001;
    if(Drop.z>0 && all(p==int2(Drop.xy))) next=Drop.z;
    Output[p]=max(next,0); // Keep official demo's negative-value clamp.
}

void GameApp::Advance(float dt)
{
    if (paused) return;
    accumulator += (std::min)(dt, .1f);
    while (accumulator >= 1.f / 60)
    {
        accumulator -= 1.f / 60;
        time += 1.f / 60;
        params.drop = {0, 0, 0, 0};
        params.a = powf(waveSpeed * params.n / 60.f, 2);
        params.land = landEnabled;
        float angle = time * .55f;
        float bx = .64f + .19f * cosf(angle), by = .49f + .23f * sinf(angle);
        float heading = atan2f(.23f * cosf(angle), -.19f * sinf(angle));
        params.boat = {bx, by, heading, boatEnabled ? .8f : 0};
        if (pending.x >= 0)
        {
            params.drop = {pending.x * params.n, pending.y * params.n, .8f, 0};
            pending = {-1, -1};
        }
        water.Step(params);
    }
}

void GameApp::Advance(float dt)
{
    if (paused) return;
    accumulator += (std::min)(dt, .1f);
    while (accumulator >= 1.f / 60)
    {
        accumulator -= 1.f / 60;
        params.drop = {0, 0, 0, 0};
        rainTimer += 1.f / 60;
        if (rain && rainTimer >= .1f)
        {
            rainTimer = 0;
            random = 1664525 * random + 1013904223;
            float x = float(random % params.n);
            random = 1664525 * random + 1013904223;
            params.drop = {x, float(random % params.n), 3, 0};
        }
        if (pending.x >= 0)
        {
            params.drop = {pending.x * params.n, pending.y * params.n, 5, 0};
            pending = {-1, -1};
        }
        water.Step(params);
    }
}

#include "Surface.hlsli"
float4 PS(Surface i):SV_Target {
    float3 n=normalize(i.normal),v=normalize(Eye.xyz-i.world),l=normalize(float3(-.4,.85,-.3));
    float height=H(i.uv);
    if(Object.w<.5) {
        if(Info.z>.5) { float2 rg=Height.SampleLevel(LinearClamp,i.uv,0).rg;return float4(rg.rrr*.7,1); }
        float eps=1/Info.y;
        float dx=H(i.uv+float2(eps,0))-height,dz=H(i.uv+float2(0,eps))-height;
        // Same two gradient samples as the Godot material shaders.
        n=normalize(float3(-dx,1,-dz));
        float fresnel=.04+.96*pow(1-saturate(dot(n,v)),5);
        float3 reflection=Sky(reflect(-v,n));
        float spec=pow(saturate(dot(reflect(-l,n),v)),100);
        return float4(float3(.015,.09,.14)*(.4+.6*dot(n,l))+reflection*(.50+.45*fresnel)+spec*.8,1);
    }
    float3 color=float3(.025,.08,.12);
    return float4(color*(.35+.65*saturate(dot(n,l))),1);
}

建议你亲自尝试的三个小实验

01 · 把 DynamicDraw 切到船体模式，查看 F2 的 G。

选中 (3,3)，G 会被覆盖为 0.4。再看 (4,3)，进入处的 R 被覆盖为 0.4。传播公式仍然先执行，然后才判断进出并覆盖相应通道。

02 · 把 Compute 的 Damp 从 1 调到 10。

F1 仍然等于 3，因为扰动在衰减之后覆盖。F2 中心从 2.997 变成 2.97。衰减改变传播状态，但不会把一次注入先乘衰减。

03 · 把三个法线采样高度一起设为 1。

dx=dz=0，法线等于 (0,1,0)。整体抬高高度数据不会改变此处的法线；高度的局部差异才影响法线方向。

07 / 容易卡住的地方

用症状反推你该检查哪一层。

看到的现象先检查本工程的对应位置
有平面，没有波纹常量里的 Drop/Boat 是否变化；纹理是否被写；索引是否轮换Advance → Step → Height()
Debug Layer 报 SRV/RTV/UAV 冲突同一资源是否还绑定在另一个阶段或输出槽Unbind；模拟和绘制之间切换资源用途
波形似乎每帧都被重置是否把 Reset 放入正常循环，或每次都清空历史Reset 仅用于初始化、按钮或分辨率切换
Compute 没有负波不是 R32F 不能存负值，而是 Shader 做了 max(next,0)Compute_CS 最后一行
DynamicDraw 出现 G，但画面不凹H 是否取 R−G；顶点是否被 Hull 遮罩抑制，或位于边缘衰减区Surface.hlsli / Water_VS
改了模拟尺寸，模型不更细高度纹理分辨率与水面网格分辨率是两个量Reset(n) 与固定 128×128 网格
速度改变、抖动或细小波消失固定步长、传播系数、量化与截断；不要仅通过看帧率判断Advance 与 RGBA8_UNORM 写回

两个工程的现有 --validate 会进行 CPU/GPU 数值对照、重置、交互状态、分辨率和窗口尺寸检查；Debug 还检查 D3D11 调试层。这个文档的网格模型负责讲清机制，不能替代这些 GPU 测试。
